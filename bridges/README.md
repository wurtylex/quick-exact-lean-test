# Bridges: are the 100 formalizations of Theorem 2 saying the same thing?

Each file `Bridge_<i>_<j>.lean` attempts to connect agent `<i>`'s formalization to
agent `<j>`'s, for the 99 consecutive links `001→002 → … → 099→100`. One agent wrote
each bridge, working only from the two source files and [`BRIDGE_SPEC.md`](BRIDGE_SPEC.md),
with no compiler access.

## The four obligations per link

```lean
theorem cpwl  (n : ℕ)              : Agent<i>.CPWL n = Agent<j>.CPWL n
theorem relun (n k : ℕ)            : Agent<i>.ReLUn n k = Agent<j>.ReLUn n k
theorem depth (n : ℕ) (hn : 3 ≤ n) : Agent<i>.depthBound n = Agent<j>.depthBound n
theorem statement : (thm2 as agent <i> states it) ↔ (thm2 as agent <j> states it)
```
An agent that found the two genuinely different was required to *delete* the equality
and prove the negation instead, named `cpwl_ne` / `relun_ne` / `depth_ne` / `statement_ne`.

## Results (machine-checked)

All 99 bridges plus all 100 agent namespaces were elaborated in **one** Lean process
(`verification/BridgeAll.lean` regenerated by `verification/build_bridges.py`, 22,491 lines,
Mathlib v4.27.0). A probe inspects each obligation's **axiom set**, so a `sorry` — even one
laundered through another `sorry`-ed theorem — can never be reported as proved.

| obligation | PROVED | REFUTED | SORRY | missing |
|---|---:|---:|---:|---:|
| `cpwl` | 31 | 7 | 19 | 42 |
| `relun` | 11 | 0 | 87 | 1 |
| `depth` | 96 | 0 | 3 | 0 |
| `statement` | 2 | 0 | 97 | 0 |

* Bridge files compiling with **zero errors**: **31 / 99**
* Links proved on **all four** obligations: **043→044, 069→070**

### What actually got established

**The depth bound is the same everywhere.** `depth` is PROVED on **96 of 99** links.
That settles every surface variation: `⌈Real.logb 3 ((n:ℝ)-1)⌉₊` vs `⌈Real.logb 3 ↑(n-1)⌉₊`
(equal for `n ≥ 3` by `Nat.cast_sub`), and `Nat.clog 3 (n-1)` vs the real-log ceiling —
equal unconditionally by Mathlib's `Real.natCeil_logb_natCast`. Agent `091`'s `Nat.clog`
encoding, which looked like an outlier, is provably correct.

**The `CPWL` split is real, and 7 links prove it.** These carry a sorry-free proof of
`∃ n, Agent_i.CPWL n ≠ Agent_j.CPWL n`:

> 030→031, 031→032, 036→037, 058→059, 059→060, 074→075, 082→083

Every one uses the same witness: `x ↦ max 0 (x 0)` at `n = 1`. It lies in a
polyhedral-subdivision `CPWL` (two half-space pieces) but *not* in a
neighbourhood-agreement `CPWL`, because no single affine function matches a kink on a
full two-sided neighbourhood. So the ~57 files defining
`CPWL` as `∀ x, ∃ i, ∀ᶠ y in nhds x, f y = g i y` state something strictly stronger than
CPWL — on connected `ℝⁿ` it collapses to the globally affine functions, and their
`theorem2` is false as written, not merely unproved.

A further 38 links attempted the same refutation and got the mathematics right but the
Lean wrong (`SORRY_NE` in the per-link table) — the agents had no compiler.

**`relun` is where the real unfinished work is.** PROVED on only 11 links. The blocker is
`exactly k` vs `at most k` hidden layers, which coincide only via the padding identity
`x = ReLU x − ReLU(−x)`. Three agents built that gadget explicitly; the rest declined.

**`statement` is almost entirely open — correctly so.** PROVED on 2 links. Agents
repeatedly noticed that once `cpwl` is refuted on one side, the biconditional reduces to
deciding the paper's actual Theorem 2, and declined to fake it. One agent did try to
route around it via both files' `sorry`-ed `theorem2`; the axiom probe caught it.

## Caveats

* 68 of 99 bridge files have elaboration errors. Agents were forbidden from running Lean
  (each `import Mathlib` costs ~4 min, so 99 of them was not viable), and wrote proofs
  blind. Failed tactics are recorded by Lean as `sorryAx`, so they show as `SORRY`, not as
  false `PROVED` — the counts above are floors, not estimates.
* `090→091` was dispatched twice and the retry overwrote a stronger earlier version; it
  reads weaker here than it needs to.
* Prose in the agent reports ("which file is more faithful") is opinion and was **not**
  verified; a couple of agents got it backwards. Only the table above is checked.

## Layout

```
bridges/
  Bridge_001_002.lean … Bridge_099_100.lean   99 bridge files
  BRIDGE_SPEC.md                              the spec every bridge agent followed
  verification/
    bridge_report.md      full per-link table + first error per failing link
    bridge_analysis.json  machine-readable verdicts
    bridge.log            raw Lean output
    build_bridges.py      splices agents + bridges into BridgeAll.lean
    bridge_prelude.lean   the axiom-inspecting probe
    analyze_bridges.py    turns the log into the report
```

Reproduce:

```sh
cd bridges/verification && python3 build_bridges.py
cd /Users/panda/Desktop/Lean/primes
lake env lean -DmaxErrors=100000 ../quick-test/harness/BridgeAll.lean > bridge.log 2>&1
python3 analyze_bridges.py bridge.log
```
(`-DmaxErrors` matters: the default cap of 100 aborts the run a fifth of the way in.)
